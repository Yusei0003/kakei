# kakei

LINEにレシート写真・PayPay/クレジットカード/通帳の明細ファイル・金額のテキストを送ると、
自動で収支を記録し、あとでダッシュボードでカテゴリ別・月別に確認できるようにするための個人用アプリです。

## できること（現時点）

- LINEに金額を含むテキストを送ると支出として記録（例: `ランチ 800円`）。「謝金」を含む
  テキストは現金の収入として記録する（例: `謝金 5000円`）
- PayPayの取引履歴CSVを送ると、支払い・個人間送金のみを自動取り込み（チャージ・ポイント獲得は除外）
- 通帳のCSV（ゆうちょ銀行・岩手銀行の2形式に対応）を送ると、給与などの入金と、家賃・水道等の
  引落を収入/支出として自動取り込み。ATM引出やPayPayチャージなどの内部移動は自動で除外する
- クレジットカード（楽天カード）の利用明細PDFを送ると、取引を自動取り込み（`mupdf`でテキスト抽出）
- 一度カテゴリを選んだ店は、次回以降そのカテゴリを自動適用（個人間送金・振込は毎回確認）
- 日付・金額・収支の別が近い取引を別ソース間の重複候補として検出し、LINEで確認
- レシート写真のOCR（Google Cloud Vision）は下記の「既知の制約」を参照
- ダッシュボード（`/`）で月別の収入・支出・収支、カテゴリ別支出のグラフ、直近6か月の推移、
  最近の取引、要確認リスト（カテゴリ未確定・重複候補）の解消、学習済みカテゴリの編集、
  取引の削除ができる（実データが無い間・Supabase未設定の間はそれぞれ案内を表示）
- 毎月1日 09:00 JSTに「今月分の明細を送ってください」とLINEにリマインド通知が届く
  （Vercel Cron Jobsで実行）

## 必要なアカウント・APIキー

1. **LINE Developers**（https://developers.line.biz/）
   - Messaging APIのチャネルを新規作成
   - チャネルシークレット → `LINE_CHANNEL_SECRET`
   - チャネルアクセストークン（長期）を発行 → `LINE_CHANNEL_ACCESS_TOKEN`
   - Webhook URLに `https://<デプロイ先のドメイン>/api/line/webhook` を設定し、Webhookを有効化
   - 応答メッセージ（自動応答）はオフにしておく

2. **Supabase**（https://supabase.com/）
   - 新規プロジェクトを作成
   - SQL Editorで `supabase/schema.sql` の内容を実行してテーブルを作成
   - Settings > API から Project URL → `SUPABASE_URL`、service_role キー → `SUPABASE_SERVICE_ROLE_KEY`
   - service_role キーは強い権限を持つため、サーバー環境変数としてのみ設定し、絶対に公開しないこと

3. **Google Cloud Vision API**（レシート写真の自動読み取りに使用、任意）
   - Google Cloudでプロジェクトを作成しVision APIを有効化（無料枠: 月1,000件）
   - APIキーを発行 → `GOOGLE_CLOUD_VISION_API_KEY`
   - 未設定でもアプリは動作するが、レシート写真を送ると「テキストで金額を送ってください」という案内が返るだけになる

4. **ダッシュボードのBasic認証**（任意だが本番では強く推奨）
   - 実際の収支データを表示するページのため、`DASHBOARD_USERNAME` / `DASHBOARD_PASSWORD` に
     任意のユーザー名・パスワードを設定する
   - 未設定の間は誰でもアクセスできてしまうので、デプロイ前に必ず設定すること

5. **月次リマインドのCron認証**（任意、リマインド通知を使う場合は設定）
   - `CRON_SECRET` に任意の乱数文字列（例: `openssl rand -hex 32` で生成したもの）を設定
   - Vercelはこの値をCron実行時のAuthorizationヘッダーに自動で使うため、
     Vercel側にも同じ値を環境変数として設定すること

`.env.example` をコピーして `.env.local` を作成し、上記の値を設定してください。

```bash
cp .env.example .env.local
```

## 既知の制約

### クレジットカード明細PDFについて

当初 `pdf-parse`（pdf.js系）で試したところ、楽天カードの明細PDFはフォントの都合で
文字がほとんど取得できませんでした。**MuPDFの公式Node.jsバインディング（`mupdf`）に
切り替えたところ問題なく抽出でき**、実際の明細PDF（2026年07月分、20取引・合計61,325円）で
1円のズレもなく一致することを確認済みです。

テキスト抽出後は1項目1行（日付→店名→支払者→支払方法→金額...の順）で並ぶ形式のため、
`src/lib/creditCardPdf.ts` の `parseCreditCardLines` は単一行の正規表現ではなく、
行のまとまり（ブロック）としてパースしています。楽天カード以外のカード会社のPDFでは
レイアウトが異なる可能性があるため、`extractionFailed`（文字がほぼ抽出できない場合）と
`transactions.length === 0`（抽出はできたが行の並びが想定と違う場合）の両方を
呼び出し側でチェックし、失敗時はLINEに「CSV形式があればそちらを」と案内しています。

### 通帳CSVについて

ゆうちょ銀行・岩手銀行の通帳CSVはどちらも文字コードが **Shift_JIS** です（PayPayのCSVは
UTF-8）。`src/lib/textEncoding.ts` がUTF-8として妥当かどうかをラウンドトリップで判定し、
妥当でなければ自動でShift_JISとして読み直します。

行の大半はATM引出・PayPayチャージ・口座内の振替といった、家計の増減を伴わない内部移動
です。`src/lib/bankCsv.ts` はこれらを摘要のパターンから検出して除外し、前後の残高が
入出金額と整合しているかも検算します（実データ953行+20行で不一致0件を確認済み）。
他の金融機関のCSVを追加する場合は、ヘッダーの文字列で形式を判別する部分と、除外パターンの
正規表現を追加してください。

### カテゴリ

`src/lib/categories.ts` に固定リストとして定義しています。追加・変更する場合は
`supabase/schema.sql` の `check` 制約も同時に更新してください。LINEのクイックリプライは
最大13項目までのため、支出カテゴリはちょうど上限に収めています。

### 「謝金」の自動判定について

テキスト入力に「謝金」という語が含まれていると、現金の収入として自動記録します（金額の
確認なしに確定するため、謝金を**支払った**場合も誤って収入として記録されてしまいます）。
ダッシュボードの「最近の取引」から削除はできますが、カテゴリや収支の別を直接修正する画面は
無いため、修正したい場合は削除してLINEからテキストで送り直してください。

### ダッシュボードについて

- 単一ユーザー運用の前提で、`transactions` テーブルに最初に現れたLINEユーザーIDを自動的に
  「本人」とみなす（`DASHBOARD_LINE_USER_ID` で明示的に指定も可能）。データが1件も無い間は
  案内画面を表示する
- 月別の集計はUTCではなく **JST の暦月** で区切る必要があるため、対象ユーザーの確定済み取引を
  まとめて取得したうえで `src/lib/dashboardData.ts` 内でJSTに変換して集計している
  （個人利用规模のデータ量を前提にした実装で、件数が大きく増えた場合はSQL側での集計に
  切り替えることを検討する）
- カテゴリ確定・重複解決・学習済みカテゴリの編集・削除はServer Actions（`src/app/actions.ts`）
  で行い、別途REST APIは用意していない
- Next.js 16では `middleware.ts` が `proxy.ts` に名称変更されているため、Basic認証は
  `src/proxy.ts` に実装している

### 月次リマインドについて

`vercel.json` の `crons` 設定で、毎月1日 09:00 JST（`0 0 1 * *`、UTC基準）に
`/api/cron/monthly-reminder` を呼び出し、`resolveLineUserId()` で特定した本人へ
LINEのプッシュメッセージで明細送付を促します。まだ一度もLINEでやり取りしていない
（`transactions` テーブルが空の）間はスキップします。

Vercelの無料プラン(Hobby)でもCron Jobsは利用できますが、実行のタイミングはVercel側の
混雑状況により多少前後することがあります。プロキシのBasic認証は `api/cron/` 配下を
除外しているので、代わりに `CRON_SECRET` で認証しています。
